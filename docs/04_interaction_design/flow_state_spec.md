## 二、全链路交互总览

### 2.1 三阶段串联

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                     Agent 智能文档审核系统 — 全链路交互                          │
│                                                                              │
│  阶段 1: 上传与解析                  阶段 2: AI 审核执行       阶段 3: 人工审批  │
│  (Teammate 1)                       (Teammate 2)            (Teammate 3)     │
│                                                                              │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌──────────┐   │
│  │ 工作台   │───▶│ 上传校验 │───▶│ 解析任务 │───▶│ AI 审核  │───▶│ 人工审批  │   │
│  │ 入口     │    │ 格式/OCR │    │ 解析进度 │    │ 4 Agent  │    │ 高/中/低  │   │
│  └─────────┘    └─────────┘    └─────────┘    └─────────┘    └──────────┘   │
│       │              │              │              │              │          │
│  用户进入系统    拖拽/选择文件   解析前信息补充   多Agent并行执行   分级处置      │
│  新建 vs 继续    客户端预检      排队/进度/失败   断点恢复         同意/编辑/驳回 │
│                                 触发下一阶段                      提交/暂存    │
│                                                                              │
│  输出: 文档已解析    输出: 解析完成 / 解析失败     输出: AI_RISK_FLAGGED         │
│        → 阶段2         → 重试/阶段2               → 阶段3                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 三阶段职责边界

| 维度 | 阶段 1: 上传与解析 | 阶段 2: AI 审核 | 阶段 3: 人工审批 |
|------|-------------------|----------------|-----------------|
| **起点** | 用户进入系统 | 解析完成 | AI 审核完成 |
| **终点** | 解析完成 / 解析失败 | 审核完成 / 失败 / 中断 | 报告提交 / 暂存草稿 |
| **AI 角色** | 辅助（OCR + 条款提取） | 主导（4 Agent 并行） | 无（仅提供解释数据） |
| **人工角色** | 配置（文档类型/Playbook） | 监控 + 异常处理 | 决策（approve/edit/reject） |
| **关键约束** | MVP 仅 PDF/DOCX + NDA | 4 Agent 并行 ≤ 5min | 高风险不可跳过 |

## 三、核心设计要点汇总

### 3.1 阶段 1 — 上传与解析（Teammate 1）

| 设计要点 | 说明 | 差异化价值 |
|---------|------|-----------|
| OCR 双模式 | "立即处理"和"后台处理并通知"可选 | 竞品普遍仅支持等待模式 |
| 解析进度透明展示 | 按 Agent 维度（4 个 Agent 各展进度条） | 区别于竞品的"黑盒"进度条 |
| 解析断点续传 | 失败后利用 Checkpointer 从失败点恢复 | 已完成 Agent 结果不丢失 |
| 6 域 16 节点 | 每个节点四要素：触发→响应→操作→下一状态 | 可直译前端页面规划 |

### 3.2 阶段 2 — 中间审核状态（Teammate 2）

| 设计要点 | 说明 | 差异化价值 |
|---------|------|-----------|
| 4 Agent 并行进度可视化 | 风控 Agent 和合规 Agent 并行卡片 + 实时计数器 | 竞品无此细分展示 |
| Checkpointer 断点恢复 | "从中断处继续"用户心智模型 | 不暴露技术"断点"概念 |
| 部分成功差异化处理 | 三区结果面板（完成区/待审区/全局操作区） | 竞品普遍全有或全无 |
| 9 状态生命周期 | 已创建→排队→执行→完成/失败/取消/部分成功/暂停/恢复 | 覆盖全部异常路径 |

### 3.3 阶段 3 — 人工审批（Teammate 3）

| 设计要点 | 说明 | 差异化价值 |
|---------|------|-----------|
| 高风险不可跳过 4 层约束 | 工作流 interrupt() + API 409 + UI 置灰 + 并发锁 | 竞品普遍无此精细约束 |
| 中风险标记区分 | `UNREVIEWED_AUTO_PASSED` vs `REVIEWED_CONFIRMED` | 影响审计权重和法律追溯 |
| 8 操作 6 要素规范 | approve/edit/reject/batch/spot-check/escalate/manual-add/submit | 可直译 API 端口和数据模型 |
| 手动补充标记 5 条设计理由 | MVP 单人场景直接生效、心流不打断、来源区分可追溯等 | 有据可查的设计决策 |
| 11% 分层随机抽样 | 确定性种子避免"刷新绕过" | 低风险审计可行 |
