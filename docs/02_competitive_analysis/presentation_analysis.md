## 1. 执行摘要

### 1.1 研究范围

本报告对 9 个主流 AI 合同/法务文档审阅产品的「审核结果呈现方式」进行了系统性拆解，聚焦于**用户看到什么、如何交互、如何决策**的全链路呈现体验。

### 1.2 核心发现

1. **呈现方式正在从「列表式」向「沉浸式」演进**：传统产品（Kira）以列表和表格为主，新一代产品（Ironclad Jurist、Luminance）在视觉化风险映射、原生 Word 内嵌体验方面有显著突破。

2. **"Word 优先 vs Web 优先"是最核心的产品分水岭**：Spellbook、Ironclad Jurist、LegalOn 坚定选择 Microsoft Word 内嵌路线（"Meet lawyers where they work"），而 Robin AI、Lexion、Evisort 则走 Web 平台路线提供更丰富的仪表盘和分析能力。

3. **Playbook 驱动的差异化呈现是竞争焦点**：Ironclad 的"Preferred → Fallback → No Redline"三位一体的立场切换、LegalOn 的 50+ 预置 Playbook、Spellbook 的基准对比，都在将内部标准外部化为审查界面的核心导航结构。

4. **解释性数据展示严重不足是行业通病**：多数竞品只提供风险标记和修改建议，但缺少"为什么这样判断"的透明解释链条。置信度评分、法规原文引用、历史相似条款参考在几乎所有产品中都是空白或极其薄弱的。

5. **审计追踪的呈现一致性很差**：有的产品（Ironclad）提供丰富的活动日志和版本历史，有的产品（Spellbook、Harvey）几乎没有面向用户的审计可视化。这使得 HITL 场景下的决策追溯存在结构性缺失。

6. **移动端体验是全面的市场空白**：9 个产品中无一提供有意义的移动/平板审查体验，所有产品均设计为桌面端使用。这限制了出差律师或需要快速审批的高管的移动场景。

### 1.3 对自建产品的启示

| 发现 | 启示 |
|------|------|
| 竞品多数是"黑箱审查"——只给结果不给过程 | 我们可以在**解释性数据展示**上建立差异化优势 |
| 审计追踪的可视化普遍薄弱 | 内置的 **HITL 决策链路可视化**可成为核心卖点 |
| 移动端集体缺失 | 提供**响应式 Web 审查界面**可覆盖未被服务的场景 |
| 多文档关联导航几乎没人做 | **合同家族图谱导航**是显著的差异化机会 |
| 缺少 AI 审查结果的可编辑性 | 允许用户**修正 AI 误判并反馈学习**可形成闭环 |

## 3. 逐产品深度拆解

### 3.1 Ironclad

**来源**: [Ironclad 产品页](https://ironcladapp.com/product/jurist) | [Ironclad 帮助中心](https://support.ironcladapp.com/) | [Ironclad Journal](https://ironcladapp.com/journal/legal-ai/best-ai-tools)

#### 3.1.1 风险项展示

Ironclad 采用**双轨风险呈现模式**：

- **CLM 工作流内的 Playbook Usage 侧栏**：合同审阅阶段，右侧信息面板下方展示"Playbook Usage"列表，逐条列出需要注意的合同条款，每条附带快速跳转链接。
- **Jurist 独立 AI 助手的会话式风险分析**：用户上传合同后，Jurist 分析并标记风险条款。

**风险分级方式**: 通过 Playbook 配置区分"Approved Language (Preferred Position)"和"Non-Standard Language (Fallback Position)"。非标准语言出现时需要 **Clause Approver**（通常为法务团队成员）特别批准，形成隐式的二级风险标记。

**风险分类**: 通过 190+ 预置 AI Clause Types 实现分类（如 Indemnification、Limitation of Liability、Termination、Confidentiality 等），每个分类可独立配置 Playbook 规则。

**仪表盘/概览页**: Ironclad 的 CLM Analytics 仪表盘提供合同周期时间、谈判模式、绩效指标的可视化报告。但风险摘要并非其主仪表盘的核心组件——风险信息更多呈现在单个合同的审阅流程中。

**排序与筛选**: Playbook Usage 列表按条款在文档中出现的位置排列，支持按 AI Clause Type 筛选。

**风险趋势**: Ironclad 的版本对比功能支持追踪同一合同在多次谈判中的条款变化，但**跨合同的聚合风险趋势分析**未见公开描述。

#### 3.1.2 原文定位与导航

- **原文定位**: 点击 Playbook Usage 列表中的条款项，跳转到文档对应位置。
- **高亮方式**: 在 Word 内联工作流中，使用标准 Word 修订标记（Track Changes）显示变更。非标准条款在侧栏中被标记。
- **并排视图**: 支持——Jurist 左侧面板（活动日志）+ 右侧主区域（工作文档）。
- **条款跳转**: 未在公开文档中找到条款间超链接跳转的描述。
- **文档内搜索**: Jurist 提供文档内搜索和自然语言查询能力（"Ask Jurist"）。
- **多文档关联导航**: 支持 Compare Documents 功能，但大规模多文档关联图谱未见。

#### 3.1.3 中间解释性数据展示

- **AI 判定理由**: 每次 Redlining 建议附带"Suggestion Rationale"——解释改了什么、为什么重要、如何解决。这是 Ironclad 最强的差异化之一。
- **Playbook 对比**: 用户在 Redline 弹窗中可看到多个建议方案（从最保守到最激进），最后一项为公司的 Preferred Position。
- **法规引用**: 未在公开文档中找到自动法规引用的描述。
- **置信度/风险评分**: 未见公开的风险评分可视化。
- **历史相似条款**: 未提及。
- **数据可追溯性**: Playbook 规则来源明确（由法务团队配置），Jurist Logs 面板记录每一步 AI 操作。

#### 3.1.4 修改建议与协作

- **修改建议形式**: AI 生成多个修改建议（least to most aggressive），每个建议包含替换文本，用户点击"Approve + Insert into document"应用。Jurist 可生成 **"Summary of redlines"伴随文档**——汇总所有建议变更，适用于长合同（40+ 页）的快速审阅；以及"Extracted rules from playbook"伴随文档。
- **一键接受/拒绝**: 支持——Approve（接受非标准语言）或 Redline（生成 AI 建议）两个按钮；Redline 弹窗中可选具体建议并一键插入。支持 Accept all changes（批量接受全部修改）、逐条接受/拒绝。
- **手动编辑 AI 建议**: 支持——用户可在 Jurist 中编辑文档，通过 Position Toggling 在 Preferred / Fallback / No Redline 间切换，还可使用 **"Rewrite with Input"** 选项用自己的语言重写条款。
- **多人协作**: CLM 工作流内置审批路由和批注功能；内外部评论分离；@提及；Activity Feed 时间线；Turn Tracking 追踪谈判轮次。**反模式**: 评论、版本变更、审批、审计事件全部混合在同一 Activity Feed 中，缺乏分类过滤，可能在复杂合同中造成信息过载。
- **版本对比**: 自动追踪版本历史；支持原合同 vs. AI 修改版的对比。**三路合并**处理来自不同编辑环境（Ironclad Editor、Google Docs、Word）的冲突变更。

#### 3.1.5 报告与导出

- **报告格式**: CLM 仪表盘可生成报告；合同可导出为 .docx。
- **可定制性**: Playbook 高度可定制（190+ Clause Types + 自定义规则）。
- **Redline 导出**: 生成标准 Word 修订文档。
- **审计追踪**: 完整的活动日志、版本历史、审批记录和 Jurist Logs。
- **数据导出**: API 可用；支持与 Salesforce 等系统集成。
- **集成报告**: 与 CRM（Salesforce）、电子签名（DocuSign）集成。

### 3.2 Kira Systems

**来源**: [TrustRadius](https://www.trustradius.com/products/litera-kira/reviews) | [G2](https://www.g2.com/) | 行业评测文章

#### 3.2.1 风险项展示

Kira 的界面以**功能导向**为主，2025 年推出了重大 UI 改版：

- **呈现布局**: **双轨模式**——(a) 传统提取网格（Extraction Grid）以表格呈现结果；(b) **2025 年新推出 Analysis Chart（类 Excel 网格视图）**——这是 Kira 近年来最重大的 UI 变革，以电子表格布局展示所有文档的提取语言和答案，每行代表一个文档/条款，每列代表一个智能字段，支持显示/隐藏列、调整行高、全屏切换。用户反馈搜索范围过大和输出格式自定义受限是两个主要痛点。
- **风险分级**: **无显式风险分级系统**。Kira 定位为"提取工具"而非"风险判定工具"——它告诉你条款在哪，但不对风险做判断。**Partial Matching（部分匹配）**功能通过图表展示每条提取的变更数量，使用滑块调整匹配度阈值——这是 Kira 最接近风险指示的能力。
- **风险分类**: 通过 **1,400+ 预置智能字段**（非 1,000）实现自动分类，覆盖 40+ 实质性领域（M&A、商业合同、租赁等）。Quick Study 允许用户通过自然语言创建自定义字段。
- **仪表盘/概览页**: **极其有限**。Kira 的核心界面是项目管理面板（任务分配、进度跟踪），而非风险摘要仪表盘。
- **排序与筛选**: 支持按条款类型筛选提取结果，按相关性排序。
- **风险趋势**: 不支持——Kira 不追踪跨版本风险变化。

**UI 反模式**: 用户反馈"搜索范围过大"和"输出格式自定义受限"是两个主要痛点。Kira 的功能强大但在呈现上偏"工程工具"风格，缺乏面向商业决策者的直觉化体验。

#### 3.2.2 原文定位与导航

- **原文定位**: 点击提取结果跳转到文档中原句位置。
- **高亮方式**: 识别的条款文本在文档中被高亮标记。具体颜色编码方式因项目配置而异。
- **并排视图**: 部分支持——列表视图 + 文档视图并行，但不是真正的左原文/右分析的沉浸式并排。
- **条款跳转**: 不支持条款间引用跳转（如定义 → 使用处）。
- **文档内搜索**: 支持全局搜索，但用户反馈"跨所有文档搜索过于宽泛"。
- **多文档关联导航**: **不支持**——Kira 将文档视为独立实体，用户反馈"系统不理解文档家族（主合同 + 修订协议）"。

**UI 反模式**: 文档上传后无法重命名（用户反复投诉）；Smart Fields 无法重命名以匹配项目术语；Quick Study 窗口使用字母排序导致难以滚动查找。

#### 3.2.3 中间解释性数据展示

- **AI 判定理由**: Kira 不对条款做风险判断，因此不提供"为什么这是风险"的解释——只提供"这里有一个 X 类型的条款"。2025 年新增的 Chat 界面和 Analysis Chart 中的内联引用（Built-In Citations）改善了可追溯性，每个结果旁展示 exact source clauses。Smart Summaries 用 AI 生成条款摘要辅助 DD 报告起草。
- **Playbook 对比**: 不支持标准 Playbook 对比。但 April 2025 新增 **Partial Matching Redlining**——在部分匹配中可视化展示提取结果与基线的差异，滑块调整阈值后批量接受/拒绝。
- **法规引用**: 不支持。
- **置信度/风险评分**: **Quick Study 自定义字段提供高精度置信度评分**——这是 Kira 独有的差异化功能。内置模型无此能力。
- **历史相似条款**: Quick Study 通过用户反馈实现增量学习（模型级），但**不向用户展示"历史上类似条款如何决策"**。
- **数据可追溯性**: Quick Study 自定义模型训练数据可追溯。**差分隐私算法**保护训练数据保密性——Kira 宣称是法律 AI 行业首创，数学上保证训练数据不可逆向工程。内置模型的训练数据不透明。

#### 3.2.4 修改建议与协作

- **修改建议**: **不提供**。Kira 是审查/提取工具，不生成修改建议或 redline。
- **一键接受/拒绝**: 不适用。
- **手动编辑**: 用户可以在提取结果上手动修正标记，但这不是 AI 建议的编辑。
- **多人协作**: 支持多审阅者并行工作，有项目管理级别的任务分配和进度跟踪，但缺乏文档级的实时讨论和批注功能。
- **版本对比**: 不支持。

#### 3.2.5 报告与导出

- **报告格式**: 支持导出为 Excel 电子表格和 Word 报告。用户反馈"输出格式自定义受限"。
- **可定制性**: Quick Study 支持训练自定义模型，但导出报告模板的定制性有限。
- **Redline 导出**: 不支持。
- **审计追踪**: 项目管理级别跟踪（谁分配了什么任务），但缺乏细粒度的条款级决策审计。
- **数据导出**: 通过 Excel/CSV 导出；与 iManage、NetDocuments 集成。
- **集成报告**: 与文档管理系统（DMS）集成。

### 3.3 Luminance

**来源**: [Luminance 官网](https://www.luminance.com/) | [案例研究](https://www.luminance.com/customers/) | [产品手册](https://www.luminance.com/files/brochures/)

#### 3.3.1 风险项展示

Luminance 在风险可视化方面是行业差异化最显著的产品：

- **呈现布局**: 独有的**热力图（Heatmap）/ 文档映射（Visual Document Map）** 视图——每块"瓷砖"代表一组概念相似的文档，颜色深度表示已审阅比例。3D 图形和交互式 Widget 提供超过 1,000 种开箱即用的可视化维度。
- **风险分级**: **交通灯分析（Traffic Light Analysis）** 是最受用户称赞的功能：
  - 绿色——可接受的条款，无需关注
  - 琥珀色——值得审阅的条款
  - 红色——有问题/不可接受的条款
- **风险分类**: 基于 1,000+ 法律概念自动分类；通过模式识别（Pattern Recognition）进行异常检测——无需用户预定义所有规则。
- **仪表盘/概览页**: **极强的仪表盘**——交互式虚拟仪表盘提供数据丰富的全局视图，涵盖法域分布、语言分布、条款类型和异常检测。
- **排序与筛选**: 支持可筛选的条款分类（如德文界面中的"Unzulassig / Unfair / In Ordnung / Zur Neubewertung"），一键聚焦。
- **风险趋势**: 跨文档的异常检测隐式提供趋势感知，但**无明确的合同版本间风险变化追踪**。

**设计亮点**: Luminance 是唯一将文档审查结果以空间化、视觉化方式呈现的产品。交通灯分析被用户描述为"非常酷且极易使用——我的团队很喜欢"。

#### 3.3.2 原文定位与导航

- **原文定位**: 通过热力图点击钻取到具体文档和条款位置。
- **高亮方式**: Word 集成侧栏中，使用颜色编码标记条款风险等级。
- **并排视图**: 支持——Microsoft Word 侧栏显示 AI 颜色编码分析，主区域为合同原文。
- **条款跳转**: 未明确提及条款间引用跳转。
- **文档内搜索**: 支持全文搜索和自然语言查询（通过 Lumi 聊天机器人）。
- **多文档关联导航**: 热力图本身即为多文档关联的可视化呈现，但**主合同 ↔ 修订协议的具体关联链路**未见描述。

#### 3.3.3 中间解释性数据展示

- **AI 判定理由**: **每条款三项解释数据**——Luminance 对每个标记条款提供：(1) **Summary**（条款摘要——合同中提出了什么）；(2) **Reason**（理由——为何不符合内部基准）；(3) **Mark-Up**（建议修订——可一键插入的替代语言）。这是竞品中最清晰、最具可操作性的解释模式。Lumi 聊天机器人也可回答进一步的追问。
- **Playbook 对比**: 自动对比公司 Playbook，标记差异并推荐 preferred 和 fallback 立场，提供"最有可能获得批准的替代语言"。同时展示在之前谈判中已接受/未接受的类似条款——**将历史谈判结果叠加在当前 Playbook 对比之上**。
- **法规引用**: 2026 年 1 月新增的"组合级合规仪表盘"（Portfolio-Level Compliance Dashboard）自动检查 DORA (EU)、CCPA (California) 等法规合规性，标记不合规问题（如审计权不足），但**不提供逐条款的完整法规原文引用**。
- **置信度/风险评分**: 通过交通灯颜色隐式表达（分析粒度达子条款级别），无数字评分。
- **历史相似条款**: **这是 Luminance 的显著差异化特性**——建议基于**真实历史先例**而非静态 Playbook。如果组织之前与某个对手方（或类似方）谈过判，该历史影响当前交易。展示"在类似谈判中业务已接受/未接受"的对比信息，新团队成员即时获得制度知识访问。其他竞品更依赖预定义 Playbook 规则。
- **数据可追溯性**: 所有洞察附带 source-level citations 和清晰推理说明。采用 **"Panel of Judges"方法**——组合多种基础、自研和微调模型，配以超过十年实际使用积累的法律数据集。**自研法律 AI 模型（非 OpenAI 套壳）**，部分用户视此为信任优势。

#### 3.3.4 修改建议与协作

- **修改建议形式**: Word 侧栏提供建议的先例/替代措辞，**一键插入**文档。支持红线和绿线显示对模型版本的合规和偏离。也可通过分步检查清单（Checklist）形式引导逐项完成。
- **一键接受/拒绝**: 支持——侧栏一键插入建议措辞。**Lumi Go 自动谈判**（2024.12）：对手方也可收到实时 AI 反馈，告知其修改是否可能被接受，并一键插入高通过率替代语言——将 AI 辅助从"己方"扩展到了"双方"。
- **手动编辑 AI 建议**: 支持——在 Word 环境中自由编辑。
- **多人协作**: 内置工作流工具——自动任务分配、笔记、批量文档分配、项目经理实时进度监督。**反模式**: 第三方评测指出协作功能相对较弱——审查结果通常需要通过其他渠道导出或沟通，Luminance 不是作为安全协作工作空间设计的。
- **版本对比**: 支持与模型版本的对比（红线/绿线）。**Lumi 版本对比**：将新草案与早期版本对比，解释变更内容和风险敞口如何变化。引入"文档家族"概念——将修正、附属信函和相关协议视为"不断演变的关系"进行整体比较。

#### 3.3.5 报告与导出

- **报告格式**: 交互式仪表盘导出 + Word 侧栏生成的文档。
- **可定制性**: Widget 化仪表盘可配置，1,000+ Widget 可选组合。
- **Redline 导出**: 通过 Word 集成实现。
- **审计追踪**: 组合级合规仪表盘提供审计合规轨迹。
- **数据导出**: 未公开详细格式。
- **集成报告**: 与 Microsoft Word 深度集成。

**设计亮点**: Luminance 的 Lumi 聊天机器人（"Legal-Grade chatbot"）让用户用自然语言查询组合级合同数据，如"哪些销售协议可转让但需要书面同意？"，极大地降低了仪表盘的使用门槛。

### 3.4 Harvey

**来源**: [Harvey 官网](https://harvey.ai/) | 行业评测 | Sacra 分析

#### 3.4.1 风险项展示

Harvey 在 2024-2025 年经历了从纯聊天助手到多界面统一平台的重大演变。当前界面包括：Web 平台（Assistant + Vault + Review Tables）、Microsoft Word Add-In、Command Center 分析仪表盘。定价约 $1,000-$1,200/律师/月。

#### 3.4.1 风险项展示

- **呈现布局**: **多层次呈现**——(a) **Review Tables（电子表格视图）**：以结构化网格呈现审阅结果，每行代表一份合同/条款，每列代表一个审阅维度（如"管辖法律""转让条款"）；每单元格展示 Answer（答案摘要）+ Reasoning（推理过程），用户可展开查看完整分析链；(b) **Word Add-In Playbook Review**：文档内逐条分析，结果以 Word 原生评论和 Track Changes 形式呈现；(c) **Assistant 对话界面**：保留原始聊天能力作为补充查询方式。
- **风险分级**: **三级颜色编码**——Acceptable（绿色/可接受），Needs Review（黄色/需审查），Unacceptable（红色/不可接受）。Review Tables 中引入**多色标记系统**：红色=交易破坏项，橙色=谈判要点，黄色=标准条款——构成"数据集中风险的视觉地图"。
- **风险分类**: 按 Playbook 规则条款类型组织（赔偿条款、责任上限、终止条款等）。支持自定义 Vault Review 工作流作为可复用模板。**但无公开的高阶企业风险管理框架分类**（如"财务风险/合规风险"等）。
- **仪表盘/概览页**: **Command Center**——面向创新团队和法务运营的专用分析控制台。提供采用率数据、行业对标（peer benchmarks）、对话式 Command Center Agent（可回答数据问题并生成自定义报告）、智能产品推荐。**Review Table 状态面板**：侧边滑出面板显示审阅进度（已分配/已验证/已标记计数）。**统一首页**：个性化建议、快速访问知识源、上下文工作流推荐。
- **排序与筛选**: Review Tables 支持按列过滤排序 + 三种标记过滤器（已验证/未验证、已标记/未标记、已分配/未分配）。支持自然语言查询表格。
- **风险趋势**: Playbook 版本历史追踪规则层面变更（谁最后编辑、做了什么更改），但**无合同多次版本间的风险变化趋势分析**。

**UI 反模式**: 从聊天到结构化表格的转型仍在进行中；学习曲线陡峭（价格 $1,000-$1,200/律师/月也是显著的采用门槛）。

#### 3.4.2 原文定位与导航

- **原文定位**: **Review Tables 中句子级引用**——每个提取结果包含 sentence-level citations 可链接回源文档精确句子位置。推理字段中每个要点都**脚注到源文档具体行**。
- **高亮方式**: Word Add-In Playbook Review 中被标记的条款在文档中高亮显示，Harvey 通过 Word 原生评论系统留下解释性评论。
- **并排视图**: 未提供传统的三面板并排，但 Review Tables + Vault 文档查看器的并行使用构成功能性并排体验。
- **条款跳转**: 不支持。
- **文档内搜索**: 通过 Assistant 对话和 Vault 搜索实现。
- **多文档关联导航**: Vault 存储所有文档，可跨文档运行 Review Tables，但**无明确的合同家族图谱导航**。

#### 3.4.3 中间解释性数据展示

- **AI 判定理由**: **Review Tables 的差异化特性**——每个单元格提供 **Answer（结论摘要）+ Reasoning（推理过程）双字段结构**，用户可展开查看完整的分析推理链并脚注回原文。Playbook Review 中对每条被标记条款的评论解释了标记原因。
- **Playbook 对比**: Word Add-In 中直接在文档内运行 Playbook 审阅，对照规则检查条款——以 Word 评论和 Track Changes 形式呈现对比结果。
- **法规引用**: 在回答中提供支持性引用，但需人工验证准确性。
- **置信度/风险评分**: 无数值评分。
- **历史相似条款**: Playbook 版本历史追踪规则变更，但**不向用户展示"历史相似条款决策"**。
- **数据可追溯性**: 句子级引用 + 推理脚注提供了竞品中**最高级别的可追溯性**。

#### 3.4.4 修改建议与协作

- **修改建议形式**: **Word Add-In 中内联呈现**——以 Word 原生 Track Changes 和评论形式呈现 Playbook 驱动的修改建议。Review Tables 中可导出结果。
- **一键接受/拒绝**: 支持过滤仅查看被红线标记的文本，但接受/拒绝需在 Word 中手动操作。
- **手动编辑**: 在 Word 中自由编辑 AI 建议。
- **多人协作**: **Shared Spaces + 多色标记 + 评论**——竞品中协作能力最成熟。Review Tables 支持多人标记（红色/橙色/黄色）+ 注释 + 验证状态。
- **版本对比**: Playbook 版本历史（规则层面），非合同版本对比。

#### 3.4.5 报告与导出

- **报告格式**: Review Tables 导出 + Assistant 对话历史。与 LexisNexis、SharePoint 集成。
- **可定制性**: Playbook 可自定义；Review Tables 列可通过自然语言动态创建；条件列支持链式逻辑。
- **Redline 导出**: Word Add-In 生成的 .docx 含 Track Changes。
- **审计追踪**: Playbook 版本历史 + Command Center 采用分析。
- **数据导出**: 有限——在与 Microsoft 365 Copilot 集成后可间接利用 Microsoft 生态能力。
- **集成报告**: Microsoft 365 Copilot、LexisNexis、SharePoint（单向同步）。与现有 CLM 系统集成有限。

### 3.5 Robin AI

- **法规引用**: 未公开描述自动法规引用。

### 3.6 Spellbook

**来源**: [Spellbook 官网](https://spellbook.legal/) | [Aivoro 对比](https://aivoro.ai/comparison/robin-ai-vs-spellbook) | [LexBlog](https://www.lexblog.com/2025/05/12/draftpilot-keeps-contract-review-where-it-belongs-inside-word/)

#### 3.6.1 风险项展示

Spellbook 完全嵌入 Microsoft Word，其呈现方式与 Web 原生产品截然不同：

- **呈现布局**: **内联呈现**——风险标记、修改建议和解释全部出现在 Word 文档中。Spellbook 的侧面板提供辅助信息，但核心交互都在文档正文中。
- **风险分级**: 使用修订标记（Track Changes）和侧面板注释来传达不同类型的风险，但**无标准的三色系统**。Benchmarks 功能对比 2,000+ 行业标准来表面偏差。
- **风险分类**: 通过侧面板 Review 功能自动标记风险，按条款类型组织。
- **仪表盘/概览页**: **不存在**——一切都在 Word 内完成。用户无法看到跨合同的风险摘要仪表盘。
- **排序与筛选**: 限制——Word 内的修订窗格提供有限的导航，但无结构化的筛选。
- **风险趋势**: 不支持——单合同在 Word 内审查，无跨合同聚合。

**设计理念**: "法务部门不需要另一个应用……DraftPilot 直接集成到 Microsoft Word"（LexBlog 引用类似产品的设计理念，Spellbook 遵循相同原则）。这是**极致的"Meet lawyers where they work"**策略。

#### 3.6.2 原文定位与导航

- **原文定位**: 审查结果直接出现在文档对应位置——**无需跳转，所见即所审**。
- **高亮方式**: 使用标准 Word 修订标记——建议插入显示为彩色下划线文本，建议删除显示为删除线。侧面板提供补充信息。
- **并排视图**: **原生的上下文+结果并排**——文档正文 + Word 任务窗格内的 Spellbook 侧面板。
- **条款跳转**: 依赖 Word 原生的导航窗格和交叉引用功能。
- **文档内搜索**: 依赖 Word 原生的查找和替换；Ask 功能通过自然语言查询。
- **多文档关联导航**: 不支持——Spellbook 一次聚焦一个文档。

#### 3.6.3 中间解释性数据展示

- **AI 判定理由**: **直接出现在建议变更旁**的注释/浮动框。这是 Spellbook 的关键优势——理由在上下文中呈现，不需要切换到另一个面板。
- **Playbook 对比**: Benchmarks 功能将合同与 2,000+ 行业标准进行对比；支持 Playbook 生成和应用。**Compare to Market**（2026.01 发布，基于 2,300+ 合同类型数据集）以统计分布呈现条款相对于市场的位置——分类为 above/at/below market standard 以及 Favourable/Unfavourable。这是独特的"数据驱动的风险指示"。
- **法规引用**: 未公开描述自动法规引用。
- **置信度/风险评分**: 无——建议以二元形式呈现。Compare to Market 的统计分布提供数据驱动的风险指示，但非传统置信度评分。
- **历史相似条款**: Compare to Market 提供市场对标而非个别历史合同参考。
- **数据可追溯性**: 低——AI 决定背后的依据说明有限。Compare to Market 数据来源为"数千个类似合同"但不提供单个合同追溯（出于匿名化考虑）。

#### 3.6.4 修改建议与协作

- **修改建议形式**: 原生 Word 修订（Track Changes）——所有 AI 建议以标准修订标记的形式直接出现在文档中。这是**最符合律师工作习惯的修改呈现方式**。Review Tables 提供结构化审阅结果导出。
- **一键接受/拒绝**: 使用 Word 原生的**接受/拒绝修订**功能——最高效的接受/拒绝工作流。
- **手动编辑 AI 建议**: 完全支持——建议就是普通的 Word 修订，用户可以像编辑任何 Word 文本一样编辑它们。
- **多人协作**: 依赖 Word 原生协作功能（共同编辑、批注）+ Spellbook 的侧面板协作。**关键反模式**: Playbook 采用**单人创建者模型**——只有创建者可编辑 Playbook，其他贡献者需通过所有权转移或克隆参与。相比之下 Harvey 的 Shared Spaces 和 Review Table 多用户标记系统更加成熟。
- **版本对比**: 依赖 Word 原生的版本比较功能，但 Spellbook 本身**不提供增强版控**。

#### 3.6.5 报告与导出

- **报告格式**: 修订后的 .docx 文件本身就是"报告"。**Compare to Market** 支持导出可下载报告，可选择包含的条款。
- **可定制性**: Playbook 可定制。Compare to Market 支持自定义选择条款、选择代表方、添加交易上下文。
- **Redline 导出**: **天然支持**——每次审阅的结果就是 Redline 文档。
- **审计追踪**: 非常弱——依赖 Word 的修订历史，但**Spellbook 本身不提供结构化的审计面板**。
- **数据导出**: .docx 文件。**无公开 API**——这是 Spellbook 相比 Harvey 和 Robin AI 的显著劣势。
- **集成报告**: 无——纯 Word 内工具，不连接外部系统。

**设计亮点**: 声称节省 **1-2 小时/天**，在高频供应商审查上**快 40%**，准确率 **70-90%**。3,000+ 法务团队使用，证明了 Word 内嵌路线的市场验证。**Compare to Market** 是独特的市场对标功能（2,300+ 合同类型数据），提供类似"合同 Moneyball"的数据驱动谈判洞察。

**UI 反模式**: 完全缺乏跨合同的数据聚合能力。用户无法批量分析 10 份 NDAs 中的共同风险模式——每份合同都是独立的 Word 会话。Playbook 单人编辑模型限制团队协作。无公开 API 限制了企业集成能力。仪表盘功能极弱（Compare to Market 更像分析快照而非持续更新的仪表盘）。

### 3.7 Lexion

**来源**: [Lexion 官网](https://lexion.ai/) | [Gralio 评测](https://gralio.ai/product/lexion) | G2 (131 评论, 4.6/5) | [Lexion 专利 US20200026916A1](https://patents.google.com/)

#### 3.7.1 风险项展示

Lexion 的 AI 合同仓库为中心，风险呈现聚焦于**仓库级别的智能组织**：

- **呈现布局**: 三种呈现界面——(a) 中央合同仓库（卡片视图显示工作流状态）；(b) **Deal Review Dashboard**（专利描述：左侧提取的条款，右侧仓库标准条款，支持展开/折叠查看源文本，用户可动态接受或拒绝）；(c) Microsoft Word 内嵌的 AI Contract Assist（标记以修订格式直接出现在 Word 中）。
- **风险分级**: **二元合规判断**——基于 Playbook 规则，条款要么合规、要么不合规（被标记）。工作流级别使用颜色编码：绿色（已完成）、黄色（进行中）、红色（逾期）。但**缺乏颗粒化的条款级风险分级**——审阅者无法根据严重程度进行优先级排序。
- **风险分类**: 通过 5 个预装行业标准 Playbook + 自定义 Playbook 规则组织（用户用自然语言描述规则："用简单语言解释你希望合同遵循的规则"）。**不以传统风险类别（财务/合规/运营）组织**。
- **仪表盘/概览页**: KPI 报告仪表盘（审阅量、平均审阅时间，按任务类型/负责人/状态/时间筛选）+ 管理仪表盘（开放项目、团队进度、活动日志、讨论线程）。但 G2 反馈报告功能"有限"，部分用户反映"缺少开箱即用的预构建图表"。
- **排序与筛选**: 支持按合同类型、状态、日期、用户、标签等多维筛选生成自定义报告；支持 120+ 预定义 AI 字段搜索。
- **风险趋势**: 版本控制支持跨版本差异追踪和分支文件来源追踪，但**无显式的风险趋势仪表盘**。

**关键限制**: Lexion **缺乏文档编辑能力**——它是一个工作流/仓库工具，不是编辑器。用户无法在 Lexion 中直接修改合同文本。这意味着审阅结果的呈现止步于"标记"阶段，后续的修改操作必须在外部工具中完成。

**UI 反模式（来自 G2 用户反馈）**: AI 在**非标准协议和旧合同上不准确**；缺乏高级报告功能；Salesforce 集成定制有限；**缺乏"为什么此条款有问题"的解释**（信任度和效率的关键缺失）。

#### 3.7.2 原文定位与导航

- **原文定位**: 从仓库搜索结果跳转到合同文档中的条款位置。
- **高亮方式**: 搜索关键词高亮。
- **并排视图**: 有限——仓库列表 + 文档查看器，但**非沉浸式侧栏分析**。
- **条款跳转**: 不支持。
- **文档内搜索**: 支持全文搜索。
- **多文档关联导航**: 仓库级别的组织和检索能力提供跨合同导航，但**缺乏概念级的关联图谱**。

#### 3.7.3 中间解释性数据展示

- **AI 判定理由**: 有限——AI 合同助手加速起草和谈判，但**解释链条不透明**。
- **Playbook 对比**: 不支持（无编辑器，无对比）。
- **法规引用**: 不支持。
- **置信度/风险评分**: 不支持。
- **历史相似条款**: 通过仓库搜索隐式支持，但非AI 推荐的"相似条款参考"。
- **数据可追溯性**: 工作流日志提供操作级追踪。

#### 3.7.4 修改建议与协作

- **修改建议形式**: 提供起草辅助但不产生 AI 修改建议。
- **一键接受/拒绝**: 不支持——Lexion 不直接编辑文档。
- **手动编辑 AI 建议**: 不适用。
- **多人协作**: 这是 Lexion 的核心强项——无代码自动化工作流连接各业务部门的合同操作；集成 Slack、Microsoft Teams 用于通知和审批。
- **版本对比**: 仓库级版本管理，但**无增强的 AI 修改版对比**。

#### 3.7.5 报告与导出

- **报告格式**: 工作流仪表盘和仓库搜索。
- **可定制性**: 无代码自动化可定制。
- **Redline 导出**: 不支持（无编辑器）。
- **审计追踪**: 工作流日志记录状态变化和审批操作。
- **数据导出**: API 可用。
- **集成报告**: Salesforce、HubSpot、Microsoft Word、Slack、Microsoft Teams、DocuSign 集成。

**设计亮点**: Lexion 的"全公司合同运营中心"定位使其在**跨部门可见性**方面独一无二——法务、销售、采购、HR 共享同一个合同真相来源。但这意味着审阅特定呈现深度被广度所稀释。

### 3.8 Evisort

**来源**: [Evisort 官网](https://evisort.com/) | [G2](https://www.g2.com/) (4.7/5, 90 评论) | [RFP Wiki](https://www.rfp.wiki/) | 行业评测 | [Workday 博客](https://blog.workday.com/)

#### 3.8.1 风险项展示

Evisort 以**大规模合同分析**（11M+ 合同训练、1B+ 数据点）见长：

- **呈现布局**: 核心审阅 UX 模式是**并排视图**——左侧完整的合同草稿文本（文档查看器），右侧 AI 识别的**结构化条款列表**，按条款类型分组（Assignment、Audit、Confidentiality、Indemnification 等）。每条条款旁有**状态指示器**：绿色勾号 = 标准条款，感叹号图标 = 需要关注的例外条款。点击任一条款，左侧文档自动滚动到对应位置。
- **风险分级**: "例外优先 (exception-first)" 的二元标记——条款要么符合标准、要么需要关注。**无传统的三级颜色编码风险分级**，但 Workday Contract Negotiation Agent 对照企业 Playbook 标记风险点和不合规条款。
- **风险分类**: 230+ 预训练条款类型 + 120+ 预构建自定义 AI 模型（覆盖 HR、供应商、金融、法律、IT、销售交易等领域）；用户可通过 Document X-Ray 用自然语言定义任意追踪维度；可通过保存的 "Ask AI" 问题构建虚拟合规 Playbook。
- **仪表盘/概览页**: **Intelligent Dashboarding 是行业标杆**——4 个自填充仪表盘：(1) Documents Dashboard（合同量、付款条款、管辖法律统计、重复文件识别）；(2) Expirations Dashboard（续约和到期追踪）；(3) Tickets Dashboard（工作流工单老化分析）；(4) Workflows Dashboard（生产力指标：积压趋势、周期时间、开关率）。**自填充+交互式**——合同导入后仪表盘自动生成，所有图表支持交叉筛选和钻取至底层文档。支持拖拽式自定义仪表盘。
- **排序与筛选**: **被多个用户评为"同类最佳"**——条款级内容搜索、术语和连接符搜索、模板变体搜索；仪表盘支持完整布尔逻辑和交叉筛选。
- **风险趋势**: Workflows Dashboard 提供时间序列分析（积压趋势、周期时间）；跨文档条款级异常对比高亮偏差。

**UI 反模式（来自 G2 用户反馈）**: 学习曲线"具有挑战性"——新用户界面"一开始不知所措"；某些菜单路径"不明显"；功能可发现性是反复出现的痛点；复杂的编辑和 redlining"不总是流畅的"；仪表盘完全自定义能力受限；**AI 不支持跨关联文档分析**——如果主合同有三份修订协议，AI 不会自动关联分析，这是复杂合同层级结构的显著局限。

#### 3.8.2 原文定位与导航

- **原文定位**: 从搜索结果和相关术语跳转到合同原文。
- **高亮方式**: 搜索关键词和条款提取高亮。
- **并排视图**: 部分支持——仓库视图 + 文档查看器，但**非专用审阅并排**。
- **条款跳转**: 有限。
- **文档内搜索**: 强项——高级搜索，部分由 NLP、RAG 和 GenAI 混合驱动。
- **多文档关联导航**: 仓库级关联——相对于 Kira 的独立文档处理有进步。

#### 3.8.3 中间解释性数据展示

- **AI 判定理由**: **Workday Contract Negotiation Agent 提供明确的理由说明**——这是区别于 Lexion 的关键优势。每个编辑建议附带"清晰的即时上下文"，详细说明"为什么特定条款被标记"以及"提议的编辑如何与你的 Playbook 参数一致"。Ask AI 自然语言回答附带指向具体源条款的链接。
- **Playbook 对比**: "异常优先对比"方法——与其逐行阅读全文，AI 自动高亮条款差异和偏差。支持跨文档条款级对比（版本间、与标准库、跨合同组合）。采用"精确定位红线 (pinpoint redlines)"——仅进行最小必要修改，而非整体替换条款，使对方更容易接受。
- **法规引用**: Workday CLM 提到合规追踪（HIPAA、KYC/AML、POPIA），但**不提供 AI 自动引用具体法律条文**。
- **置信度/风险评分**: **不向用户展示数值置信度评分**。Document X-Ray 使用 AI 编排引擎在后台运行数百次实验选择最佳 LLM 和优化提示，但此过程对用户不可见。
- **历史相似条款**: 条款库和模板维护首选和备选语言作为基准；用户可训练自定义 AI 模型。但**无显式的"此条款在历史上被 80% 审阅者接受"类统计推荐**。
- **数据可追溯性**: Ask AI 答案附带源链接（指向告知答案的条款）；仪表盘钻取至底层文档。但 AI 编排引擎的内部决策过程对用户不透明。

#### 3.8.4 修改建议与协作

- **修改建议形式**: AI 辅助的条款建议，但**复杂编辑和 redlining 不总是流畅**（用户反馈）。
- **一键接受/拒绝**: 有限。
- **手动编辑 AI 建议**: 支持但与 Word 兼容性有限。
- **多人协作**: 可扩展的工作流支持大规模文档处理（Workday 在 24 小时内处理 450,000 份文档证明了规模能力），但**以操作效率为导向而非实时协作**。
- **版本对比**: 仓库中提供版本管理。

**UI 反模式（用户反馈）**: 设置的复杂性意味着**中小法务团队可能发现 Evisort 过于笨重**——分析深度是一把双刃剑。

#### 3.8.5 报告与导出

- **报告格式**: 高级分析和实时报告仪表盘。
- **可定制性**: 动态模板。
- **Redline 导出**: 兼容 Microsoft Word。
- **审计追踪**: 仓库级追踪 + REST API 审计端点（Activities、Records、Users 端点）。**ISO/IEC 42001 认证**（负责任 AI 国际标准）——Workday 宣称是唯一拥有此认证的合同管理解决方案。
- **数据导出**: API 可用。
- **集成报告**: 预构建的云存储系统集成和 Microsoft Word。

### 3.9 补充参考: LegalOn

**来源**: [LegalOn 官网](https://www.legalontech.com/) | [LegalTech Monitor](https://www.legaltechmonitor.com/) | [Artificial Lawyer](https://www.artificiallawyer.com/)

#### 关键差异化特性

LegalOn 虽不在原始 8 家核心竞品之列，但其呈现方式提供了有价值的参考：

1. **50+ 预置 Playbook（覆盖 10,000+ 法律问题，50+ 合同类型）**: 由执业律师维护的开箱即用 Playbook——Day 1 即可使用。这对没有内部 Playbook 积累的中小型法务团队是巨大的价值。

2. **Playbook Agent（2025 年 12 月）**: 让团队上传现有标准（检查清单、电子表格、邮件、培训文档），AI 自动转化为结构化、AI 就绪的 Playbook。每个 AI 生成的规则包含**可追溯的源引用**——直接解决了 Playbook 可追溯性的痛点。

3. **统一平台界面（2025 年中重设计）**: 将所有产品（审查、助手、事项管理、知识核心）整合到**单一无缝界面**。中央仪表盘支持实时通知，侧栏可编辑工作区带并排源引用。

4. **28 语言翻译**: 合同以任意 28 种语言之一编写，自动翻译成英语进行审查，编辑完成后翻译回原语言——这是其他竞品未曾覆盖的能力。

5. **Redline Review for First-Party Paper**: 审查对手方对己方合同的红线修改，评估其是否符合 Playbook 中的可接受回退立场——拓展了传统 Redline 审查的使用场景。

| **法规引用** | 未提及 | 不支持 | 组合合规监控 | **支持引用** | 未公开 | 未公开 | 不支持 | 不支持 | **自动法规映射+原文弹出** |
| **置信度评分** | 无 | 不适用 | 交通灯隐式 | 无 | 反向(拒绝低置信) | 无 | 无 | 无 | **0-100%评分+视觉温度计** |
| **历史相似条款** | 无 | 不支持 | 无 | 无 | **先例搜索** | 无 | 隐式(搜索) | 隐式(搜索) | **主动推荐(相似条款+历史决策)** |

**关键洞察**: 这是行业最大的空白领域。Ironclad 的 Suggestion Rationale 和 Robin AI 的可点击引用是仅有的亮点。但以下能力在所有竞品中**一致缺失**：
- 置信度/风险评分的定量可视化
- 法规原文的自动引用和弹出
- 历史相似条款审阅决策的主动推荐
- 端到端的 AI 推理链可视化

**这些缺失正是我们建立差异化优势的最大机会**。

## 5. UI/UX 模式与反模式

### 5.1 已验证的最佳实践（我们应该采纳）

1. **"Meet Lawyers Where They Work"（在律师工作的地方见面）** 
   - Spellbook、Ironclad Jurist、LegalOn 坚定选择 Word 内嵌
   - 约 70% 的合同审阅仍然在 Microsoft Word 中进行
   - **建议**: 提供 Word 插件作为重要渠道，但不应局限于 Word（保留 Web 端分析能力）

2. **交通灯风险编码（Traffic Light Risk Coding）**
   - Luminance 的绿/琥珀/红系统被用户描述为"非常酷且极易使用"
   - 红-橙-黄-绿递进式是事实上的行业风险颜色语言
   - **建议**: 采用五级递进颜色编码（Critical→High→Medium→Low→Info）

3. **Playbook 驱动的建议呈现**
   - Ironclad 的多方案对比（保守→激进→Preferred Position）是企业决策的最佳框架
   - 每个建议附带"Suggestion Rationale"显著提升采纳率
   - **建议**: 所有修改建议必须附解释；展示符合/偏离 Playbook 的程度

4. **可点击引用的信任建立**
   - Robin AI 的每个 AI 答案包含可点击源引用——这是防幻觉的最佳 UX
   - **建议**: 所有 AI 输出必须有可追溯的源引用（条款级锚点链接）

5. **侧栏辅助 + 正文主导**
   - Spellbook（Word 侧栏）、Luminance（Word 侧栏）、Ironclad（Playbook Usage 侧栏）的一致模式
   - **建议**: 侧栏提供分析上下文，正文保持可编辑；避免将分析放在单独的"只读"页面

6. **渐进式 UI 进化，非革命**
   - 法律行业对激进 UI 变化容忍度极低
   - **建议**: 初始 UI 应模拟熟悉的 Word 修订 + 侧栏注释模式，在此基础上渐进增强

### 5.2 已识别的反模式（我们应该避免）

1. **强制离开原生工具**
   - Web-only 平台（无 Word 集成）伤害采用率
   - **我们的应对**: Web + Word 双环境，保持一致体验

2. **开放式不可预测的审查（"巧克力盒"问题）**
   - 每次审查结果不同 → 信任丧失
   - **我们的应对**: Playbook 驱动的封闭式审查，规则透明

3. **过度 Redlining（对合规语言的误报）**
   - 不准确的建议制造而非消除工作
   - **我们的应对**: 风险分级允许用户设定灵敏度阈值；低风险自定义过滤

4. **黑箱 AI 无解释**
   - 无理由的变更让律师无法评估建议
   - **我们的应对**: 每个 AI 输出附带结构化的推理链

5. **纯聊天界面用于结构化审阅**
   - Harvey 的纯聊天模式对 50 页合同的风险全貌呈现是低效的
   - **我们的应对**: 聊天作为补充查询模式，主界面保持结构化

6. **忽视移动/平板场景**
   - 所有竞品在移动体验上都是空白
   - **我们的应对**: 响应式 Web 界面覆盖移动审批和快速审阅场景

7. **缺乏跨合同数据聚合**
   - Spellbook 只能在 Word 中处理单个文档
   - **我们的应对**: Web 仪表盘层提供跨合同的风险聚合分析

## 6. 市场空白分析

### 6.1 无人出色覆盖的领域（我们的差异化机会）

| 空白领域 | 现状 | 我们的机会 | 优先级 |
|---------|------|-----------|:------:|
| **解释性数据透明度** | 只有 Ironclad 提供 Rationale，其余几乎空白 | 结构化的 AI 推理链展示——"AI 为什么做出这个判断"的完整路径 | P0 |
| **置信度可视化** | 无竞品提供风险评分定量展示 | 0-100% 置信度评分 + 视觉指示器 + 低置信度自动升级至人工 | P0 |
| **法规原文引用** | Harvey 提供引用但不自动关联；其他竞品几乎无 | 自动检索 + 映射 + 弹出相关法规原文 | P1 |
| **历史决策推荐** | Robin AI 有先例搜索；其他竞品无 | "上次我们在类似条款中选择了方案 B，因为..." | P1 |
| **版本间风险趋势** | 无竞品提供版本间风险变化追踪 | 同一合同多次版本的风险变化 Delta 视图 | P1 |
| **移动端审阅** | 全面空白 | 响应式 Web 审查界面 + 移动推送（高风险条款需紧急审批） | P2 |
| **合同家族图谱导航** | Kira 明确定位为"独立文档处理"；其他无 | 主合同 ↔ 修订协议 ↔ 附件的可视化关联图谱 | P2 |
| **条款关系图谱** | 无竞品提供定义→引用→依赖跳转 | 条款间语义关联的可视化导航 | P3 |
| **HITL 决策可视化审计** | Ironclad 最接近；其他基本不提供 | 决策时间轴 + 每个决策节点的操作人/时间/理由/影响 | P0 |
| **多语言审阅界面** | LegalOn 支持 28 语言翻译；其他基本英语 | 中文优先 + 条款级双语对照 | P1 |
| **批量合同风险聚合** | Evisort 最接近(仓库分析)；但非审查上下文呈现 | 10 份 NDAs 同时审查→共享风险热力图 | P2 |

### 6.2 特别值得关注的竞争演变

1. **Lexion → DocuSign 收购 (2024)**: DocuSign 的电子签名 + Lexion 的 AI 仓库能力可能催生"签名前 AI 审查 + 签名后合规追踪"的闭环。
2. **Evisort → Workday 收购 (2024)**: Workday 的 HR/财务系统 + Evisort 的合同智能可能将合同审阅嵌入企业运营流程。
3. **Kira → Litera 收购 (2021)**: 文档管理 + AI 提取的整合路线。
4. **LegalOn 的 Playbook Agent (2025.12)**: 自动将非结构化的企业标准转化为结构化 Playbook——这可能成为行业标配功能。

## 7. 差异化设计建议

基于以上分析，以下是针对自建产品的审核结果呈现的差异化设计建议：

### 7.1 核心差异化支柱

#### 支柱 1: "透明推理" —— 每个 AI 判断都附解释链

```
┌─────────────────────────────────────────────────────┐
│  风险条款: 无限赔偿责任                                │
│                                                       │
│  ⚠ 风险等级: ●●●●○ (高)    置信度: 87%                │
│                                                       │
│  📋 AI 推理链:                                        │
│    1. Playbook 规则匹配: "赔偿责任上限不应超过合同金额" │
│    2. 条款检测: 第 12.3 条未设赔偿上限                  │
│    3. 法规映射: 《民法典》第 584 条（可预见规则）       │
│    4. 相似案例: 3 个历史合同中类似条款被拒绝             │
│                                                       │
│  💡 建议: 将赔偿上限设为合同金额的 1 倍                  │
└─────────────────────────────────────────────────────┘
```

**竞品基线**: Ironclad 有 Suggestion Rationale（最接近），但无人提供完整的推理链可视化。

#### 支柱 2: "决策溯源" —— 每个 HITL 中断点可审计

```
┌──────────────────────────────────────────────────────┐
│  审阅决策时间轴                                        │
│                                                       │
│  14:23  🤖 AI 标记: 第 12.3 条 无限赔偿责任 [高风险]    │
│  14:25  👤 张律师 确认: 风险等级从 高 → 关键           │
│  14:28  🤖 AI 生成: 3 个修改建议方案                    │
│  14:32  👤 张律师 选择: 方案 B（修改措辞至..."）        │
│  14:35  👤 李总监 批准: 修改建议通过                    │
│  14:36  ✅ 生成: Redline v2 已保存                      │
└──────────────────────────────────────────────────────┘
```

**竞品基线**: Ironclad Jurist Logs 最接近，但无人提供此级别的可视化时间轴。
