## 三、双方核心发现对照

### 3.1 流程视角（Teammate 1）

| 流程环节 | 行业最佳实践 | 主要差异 |
|---------|-------------|---------|
| **上传与预处理** | 12 种格式支持 + 8 种接入方式 | Ironclad 最强（API 全格式），Spellbook 最窄（仅 Word） |
| **解析与结构化** | 规则引擎 + LLM 混合架构成主流 | Kira 纯 ML 精度高但扩展慢，Harvey 纯 LLM 灵活但幻觉风险高 |
| **AI 审核** | 从单模型向多 Agent 快速演进 | Ironclad 多 Agent（提取/风控/谈判），Harvey 500+ Agent 模板库 |
| **HITL 实现** | 4 种交互模式（内联/侧栏/弹窗/列表）| Spellbook 原生 Word 体验最佳，Harvey 最弱（无有效 HITL） |
| **流程编排** | 条件分支 + 后审阅自动化 | Ironclad 最成熟，Robin AI 已消亡 |

### 3.2 呈现视角（Teammate 2）

| 呈现维度 | 行业通行做法 | 市场空白 |
|---------|-------------|---------|
| **风险项展示** | 列表/表格为主，Luminance 独有视觉映射 | 缺少交互式风险仪表盘 |
| **原文定位** | 并排视图成标配（左文档右分析） | 多文档关联导航几乎无人做 |
| **解释性数据** | 严重不足——行业通病 | **最大差异化机会**：置信度、法规引用、历史参考 |
| **修改建议与协作** | Word 内嵌派 vs Web 平台派分裂明显 | 一键接受/拒绝 + AI 建议可编辑性 |
| **报告与导出** | PDF/Word 基础导出 | 审计追踪可视化普遍薄弱 |

## 四、对自建产品的关键启示

### 4.1 必须对齐的行业基线

| 能力 | 对齐目标 | 参考竞品 |
|------|---------|---------|
| PDF + DOCX 双格式支持 | MVP 必备 | 行业标配 |
| 条款结构化提取 | 至少规则引擎 + LLM 混合 | Kira / Luminance |
| 并排视图（左文档右分析） | MVP 必备 | 行业标配 |
| 风险分级标记（高/中/低） | MVP 必备 | 行业标配 |
| 基础审计日志 | MVP 必备 | Ironclad |
| 自定义 Playbook | 差异化关键 | Ironclad / LegalOn |

### 4.2 可建立差异化的方向

| 差异化方向 | 优先级 | 为什么竞品没做好 |
|-----------|:------:|----------------|
| **解释性数据透明展示** | P0 | 竞品普遍"黑箱"——只给结果不给过程 |
| **分级 HITL 中断控制** | P0 | 竞品要么全人工（Kira）要么全自动（Harvey），缺少精细分级 |
| **审计追踪可视化** | P1 | 竞品审计呈现一致性很差 |
| **多文档关联导航** | P1 | 几乎没有竞品在做 |
| **移动端响应式审查** | P2 | 全面的市场空白 |

### 4.3 关键设计决策

1. **Web 优先 + Word 插件可选**：竞品分析显示两种路线各有优势，建议 Web 作为主平台（更强的分析能力 + 仪表盘），Word 插件作为补充（降低律所场景的学习曲线）。

2. **多 Agent 协作架构优于单模型**：Ironclad 和 Harvey 的实践表明，将提取/风控/合规/报告分离到独立 Agent 的架构，在可维护性和场景扩展性上显著优于单模型方案。

3. **HITL 是架构核心而非附加功能**：从竞品对比中可以看出，HITL 设计深度直接决定了产品的可用性上限。Harvey 虽然 AI 能力强但 HITL 薄弱，导致在需要精确性的法务场景中信任度不足。
